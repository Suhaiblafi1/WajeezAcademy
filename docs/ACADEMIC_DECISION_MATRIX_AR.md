توليد: 2026-08-17 — من قاعدة البيانات الحية.

## كيف نقرر

كل صف مهارة تحتاج قرارا واحدا من الخيارات الخمسة. لا يُضاف أي سؤال جديد ولا يتغير محرك التوصية قبل اكتمال عمود «القرار» لكل الصفوف.

الخيارات:
 1. يبقى مخرج تعلم (تغطيه دورة لاحقا)
 2. يُربط بدورة/مسار قائم (يصبح مطلوبا)
 3. يدخل التشخيص (يحتاج سؤالا جديدا — بعد المراجعة فقط)
 4. يُدمج في مهارة شقيقة
 5. يُؤرشف نهائيا

## بعد اكتمال القرارات

- «يُدمج/يُؤرشف» → تُنفَّذ عبر سكربت موثق مع تحديث مصفوفة التغطية.
- «يُربط بدورة/مسار» → ربط مرجعي فقط (CourseSkillLink / PathwaySkillRequirement) — الدورة تبقى كيانا مركزيا واحدا.
- «يدخل التشخيص» → يتطلب سؤالا جديدا بأثر موثق، ويمر على audit:diagnostic وaudit:skill-coverage قبل النشر.

## القرارات المُنفذة فعليًا في منظومة V2 (مرجع تنفيذي — لا يلغي المراجعة الأكاديمية)

> نُفذت في `src/data/catalog/v2/skill-layers.v2.json` (توليد حتمي بـ`npm run build:v2-overlays`) وتعمل في محرك V2. حالة «موقوفة أكاديميًا» تبقى كما هي حتى تُحسم المراجعة صفًا صفًا أعلاه.

| الفئة | القرار المُنفذ | الأثر في المحرك |
|---|---|---|
| المهارات المقاسة والمطلوبة بمسارات (8) | طبقة `diagnostic` + `pathway_requirement` | تُقاس بأسئلة M4 وتدخل فجوة المسار الذي يتطلبها — بالمقاس فقط |
| الأربع المقاسة بلا تغطية: `creative_thinking`، `learning_agility`، `digital_literacy`، `focus_management` | طبقة `diagnostic` + `personalization_signal` | لا تغيّر اختيار المسار؛ أثرها موثق ومحدود: انخفاض الثقافة الرقمية مع مسار رقمي يضيف «تمهيدًا رقميًا» للخطة، وانخفاض إدارة التركيز يقسّم العبء الأسبوعي، وارتفاع مرونة التعلم يرفع الوتيرة المقترحة |
| مهارات متطلبة بمسارات وغير مقيسة (≈90) | طبقة `pathway_requirement` + `learning_outcome` | **لا تُفترض أبدًا** (إلغاء قاعدة 2.5): لا فجوة ولا إتقان ولا تفسير — تظهر في «ما لم نعرفه» وتخفض تغطية دليل المهارات في الثقة |
| الـ76 الموقوفة (FIN/GOV/FAM/WELL وغيرها) | طبقة `learning_outcome` (أو `pathway_requirement` إن ارتبطت بمسار) مع `active=false` | خارج التشخيص تمامًا حتى المراجعة — لا سؤال جديد ولا إدخال متسرع |
| بقية المهارات غير المرتبطة | طبقة `learning_outcome` | مخرجات تعلم مستقبلية — خارج نطاق التشخيص الحالي |

**قاعدة صارمة مُنفذة:** أي قرار «يدخل التشخيص» من الجدولين أعلاه يتطلب سؤالًا بأثر قرار موثق (decision_impact) ويمر على `audit:diagnostic-v2` قبل التفعيل.
