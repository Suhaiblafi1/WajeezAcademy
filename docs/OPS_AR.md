# دليلُ التشغيل — سجلٌّ تاريخيٌّ لخادم Cloudways

> # ⚠️ هذا الملفُّ لم يعد ساريا — ٦ سبتمبر ٢٠٢٦
>
> **المنصّةُ على Hetzner الآن، لا Cloudways.** وكلُّ ما تحته مكتوبٌ لخادم
> Cloudways: وظيفةُ **Supervisor**، ووسيطٌ عكسيٌّ **Apache/Nginx**، وتفريغُ
> **Varnish** — **ولا واحدَ منها على Hetzner**. فالخادمُ هناك حاوياتُ
> Docker خلف **Caddy**، ولا Supervisor فيه أصلا: إعادةُ التشغيل
> `docker compose restart` لا `supervisorctl restart`.
>
> **والبديلُ الصحيح: [`deploy/README.md`](../deploy/README.md)** ومعه
> [`deploy/deploy.sh`](../deploy/deploy.sh) و[`deploy/backup.sh`](../deploy/backup.sh).
>
> ويبقى هذا الملفُّ للرجوع إليه إن احتيج إلى تاريخِ ما كان — لا ليُنفَّذ.

---

> **لمن كان هذا الملفّ:** المبرمجُ أو مسؤولُ الخوادم الذي يملك حسابَ Cloudways.
> مكتوبٌ ليُنفَّذ بلا شرحٍ شفويّ، وكلُّ خطوةٍ فيه معها سببُها وطريقةُ التحقّق.
>
> والتفصيلُ الكاملُ للنشر في [`DEPLOYMENT.md`](DEPLOYMENT.md). هذا مختصرُ ما
> **يحتاج يدَ من يملك الخادم**.

## ٢) ⚠️ العطبُ القائم — عمليّةُ Node لا يُعاد تشغيلُها بعد النشر

**العَرَض:** النشرُ ينجح، والواجهةُ تتجدّد، **والـAPI يبقى على شيفرةٍ قديمة**.

**كيف رُصد:** بعد دمجٍ في `main` عرضت صفحةُ `/courses` الإصلاحَ الجديد (٨١ دورةً
بدل ٤) — أي أنّ الملفّاتِ نزلت وبُنيت. وفي الوقت نفسِه ظلّ `‎/api/version` يردّ
بشيفرةٍ سابقةٍ للدمج: ينقصه حقلا `وقت_البناء` و`مصدر_البصمة` المُضافان في
الالتزام `0d6a7e6`.

**ولم يكن تخزينا:** حقلُ `الوقت` في الردّ يتغيّر مع كلّ طلب — فالردُّ حيٌّ،
والعمليّةُ هي التي تحمل الشيفرةَ القديمة.

**السبب:** عمليّةُ Node تبقى في الذاكرة بالشيفرة التي أقلعت بها. لا `git pull`
ولا `npm run build` يوقظانها.

> **وزرُّ «إعادة تشغيل التطبيق» في لوحة Cloudways لا يكفي** — يعيد خادمَ الويب
> (Apache/Nginx) ولا يمسّ عمليّةَ Node.

**واحتمالٌ يُفحص أوّلا:** إن لم تكن ثمّة وظيفةُ Supervisor أصلا، فالخادمُ يعمل
بأمرٍ شُغّل باليد مرّةً ولا شيءَ يعيده — **وهذا وحدَه يفسّر أنّ الـAPI لم يتحدّث
منذ إقلاعه**. وحينها إنشاءُ الوظيفة هو الحلُّ الكامل لا خطوةً منه.

```bash
ps aux | grep -i node | grep -v grep    # بأيّ أمرٍ يعمل الخادمُ الآن، ومن أيّ مجلّد
supervisorctl status                    # هل ثمّة وظيفةٌ أصلا، وما اسمُها
```

## ٣) المطلوب — وظيفةُ Supervisor

```
command      : npm start
directory    : <مجلّد التطبيق>
user         : <مستخدم التطبيق>
autostart    : true
autorestart  : true
```

`npm start` هو `tsx server/index.ts` — خادمُ Fastify نفسُه. **ولا يحتاج بناءً:**
الشيفرةُ تُقرأ من القرص عند الإقلاع، فيكفي سحبٌ ثمّ إعادةُ تشغيلٍ ليتحدّث الـAPI.

> ⚠️ **لا تغيّر المنفذ.** اقرأه من العمليّة الحاليّة (`ps aux`) — الوسيطُ
> العكسيُّ موجَّهٌ إليه أصلا، وتغييرُه يقطع `/api` كلَّه.

## ٤) متغيّراتُ البيئة — وما يُصلحه كلٌّ منها

| المتغيّر | القيمة | ماذا يقع بدونه |
|---|---|---|
| `DATABASE_URL` | عنوانُ القاعدة | **إلزاميّ.** وبدونه يحاول الخادمُ تشغيلَ قاعدةٍ مدمجةٍ للتطوير |
| `NODE_ENV` | `production` | **حارسُ أمانٍ لا زينة** — انظر التحذير أدناه |
| `API_PORT` | المنفذُ الحاليّ نفسُه | تغييرُه يقطع الوسيطَ العكسيّ |
| `API_HOST` | `127.0.0.1` | الافتراضُ المغلق. لا يُفتح إلى `0.0.0.0` إلّا إن كان الوسيطُ في حاويةٍ أخرى |
| `APP_URL` | `https://www.wajeezacademy.com` | **وقتَ التشغيل.** عليه تُبنى روابطُ البريد والعودةُ بعد الدفع — وبدونه تسقط إلى `localhost:7100`، فتصل الرسالةُ برابطٍ لا يفتح |
| `STORAGE_SECRET` | نصٌّ عشوائيٌّ طويلٌ **ثابت** | بدونه يُشتقُّ مفتاحُ توقيع الروابط من `DATABASE_URL` — **فتغييرُ عنوان القاعدة يُبطل كلَّ رابطٍ موقَّعٍ صامتا**، ووثائقُ المتقدّمين تصير غيرَ قابلةٍ للفتح |
| `RESEND_API_KEY` | مفتاحُ Resend | بدونه **لا تُرسَل رسالةٌ واحدة**: لا توثيقَ بريدٍ ولا استعادةَ كلمةِ مرورٍ ولا إشعارَ اعتماد |
| `VITE_SITE_ORIGIN` | `https://www.wajeezacademy.com` | **وقتَ البناء لا التشغيل** — يوضع في بيئة البناء، وبدونه تُعلن كلُّ صفحةٍ نطاقا خاطئا في `canonical` و`og:image` وخريطة الموقع |

> ### ⚠️ `NODE_ENV=production` حارسُ أمان
>
> مسارُ الديمو (`/api/demo/switch-role`) **يُصدر جلسةً بلا كلمة مرور لأيّ
> حسابِ ديمو — ومنها حسابُ `super_admin`**. وحمايتُه شرطان: ألّا يكون
> `DEMO_MODE=true`، **و**أن تكون البيئةُ إنتاجا (`VERCEL_ENV=production` أو
> `NODE_ENV=production`).
>
> **و`VERCEL_ENV` لا وجودَ له على Cloudways.** فالطبقةُ الباقيةُ هي `NODE_ENV`
> وحدَها. اضبطه — وقد سبق أن ضُبط عَلَمُ الديمو خطأً على الإنتاج فبقيت
> البوّابةُ مفتوحةً على الإنترنت ستّة أيّام.

## ٥) سكربتُ النشر — الخطواتُ كاملةً

في لوحة Cloudways ← **Deployment via Git**:

```bash
set -e
npm ci
npx prisma generate
npx prisma migrate deploy
npm run build                                  # يقرأ VITE_SITE_ORIGIN، ويكتب ختمَ البناء
CATALOG_IMPORT_SKIP_MIGRATE=1 npm run catalog:import
npm run catalog:publish
supervisorctl restart <اسم الوظيفة>            # ← بلا هذا لا يتغيّر الـAPI أبدا
# ثمّ: تفريغُ Varnish
```

| الخطوة | إن سقطت |
|---|---|
| `prisma migrate deploy` | **انحرافُ مخطَّط**: مساراتٌ تسقط بـ٥٠٠ على أعمدةٍ غيرِ موجودة |
| `catalog:import` | **الكتالوجُ الذي يراه المتعلّم مجمَّد** — `‎/api/public/core-catalog` يقرأ الجداولَ الحيّة |
| `catalog:publish` | **محرّكُ التشخيص مجمَّد** على لقطته القديمة |
| `supervisorctl restart` | **الـAPI كلُّه مجمَّد** — وهو العطبُ الموصوف في §٢ |
| تفريغُ Varnish | Cloudways يخزّن HTML ويعلو على `.htaccess` |

## ٧) أوّلُ مديرِ نظام — لا يوجد بريدٌ «إداريٌّ» بالإعداد

**لا متغيّرَ بيئةٍ يعيّن المدير، ولا بريدَ مكتوبا في الشيفرة.** التسجيلُ من
الموقع يمنح دورَ `learner` وحدَه، وتعيينُ الأدوار من الشاشة محكومٌ بالرتبة:
**لا يمنح `super_admin` إلّا `super_admin`**. فقاعدةٌ بلا مديرِ نظامٍ لا سبيلَ
إليها من الواجهة أصلا — وهذا السبيل:

**والبريدُ المعتمَد بقرار صاحب المنصّة: `suhaib@wajeez.co`**

```bash
# ١) يسجّل صاحبُ المنصّة حسابا عاديّا من الموقع بهذا البريد
# ٢) ثمّ من الخادم — عرضٌ بلا كتابة أوّلا:
DATABASE_URL="…" npx tsx scripts/promote-super-admin.ts suhaib@wajeez.co

# ٣) وإذا صحّ ما يعرضه:
DATABASE_URL="…" npx tsx scripts/promote-super-admin.ts suhaib@wajeez.co --apply
```

يُضيف الدورَ ولا ينزع شيئا، ويسجّل الفعلَ في سجلّ الأثر. والصلاحياتُ تُقرأ من
القاعدة في كلّ طلب — فيكفي أن يُحدِّث الصفحةَ.

> ### أيُّ بريدٍ يُختار؟
>
> **بريدُ شخصٍ يقرأ صندوقَه فعلا** — لأنّه بريدُ دخولٍ لا بريدُ منصّة: عليه
> يصل توثيقُ الحساب واستعادةُ كلمة المرور.
>
> **ولا يُستعمل أحدُ عناوين الأكاديميّة الستّة** (`no-reply@` · `support@` ·
> `privacy@` · `legal@` · `billing@` · `calendar@`). تلك عناوينُ **المنصّة**
> تُرسل منها وتستقبل عليها، وليست حساباتِ أشخاص. و`no-reply@` خاصّةً لا يقرأ
> أحدٌ ما يصله — **فحسابُ إدارةٍ عليه يعني استعادةَ كلمةِ مرورٍ لا تصل أبدا**.
>
> وإن أُريد بريدٌ على النطاق الجديد فليكن **بعد** أن يصير صندوقا يستقبل فعلا.
>
> ⚠️ **وملاحظةٌ على `wajeez.co`:** هو نطاقٌ غيرُ نطاق الموقع، والحسابُ يعمل به
> ما دام صندوقُه يستقبل. **فإن تُرك النطاقُ أو انتهى اشتراكُه ضاعت استعادةُ
> كلمة المرور معه** — والحسابُ لا يُفتح. فإن عُزم على تركه يوما، **يُغيَّر بريدُ
> الحساب قبل ذلك لا بعده.**

## ٨) بعد أن يعمل كلُّ ما سبق

- **نسخةٌ احتياطيّةٌ جُرّبت استعادتُها** — لا نسخةٌ موجودة، بل نسخةٌ أُثبت أنّها تعود
- **المُشغِّلُ الخلفيّ**: `WORKER_ENABLED=on npm run worker` بمشرفٍ يعيده، **وعمليّةٌ واحدةٌ فقط**
  — ⚠️ **ولا يُشغَّل قبل أن يصل البريدُ فعلا**: الطابورُ المتراكمُ يتحوّل كلُّه
  إلى «فاشل» في دورةٍ واحدة، والتعافي يدويٌّ صفّا صفّا. جرِّب `npm run worker:once`
  أوّلا وتحقّق أنّ «سقط ٠»
- **حذفُ بوّابات المعاينة الداخليّة** من `/auth` قبل فتح التسجيل للعموم
