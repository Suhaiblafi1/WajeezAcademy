# رسالة إلى المبرمج — تركيب النشر الآليّ (Docker · Hetzner)

> نصٌّ جاهزٌ للإرسال كما هو. يُحدَّث هنا إن تغيّر شيء، فلا تُنسَخ نسخةٌ ثانيةٌ
> تفترق عنه.

---

**أوّلا — ألغِ الرسالةَ السابقة.**

الرسالةُ التي وصلتك عن النشر كانت مبنيّةً على أنّ الاستضافة Cloudways وأنّ
الخادمَ عمليّةٌ تحت Supervisor. وذلك خطأ، وأنا مصدرُه: أخذتُه من
`docs/DEPLOYMENT.md` ولم أقِسه. والقياس:

```
dig +short www.wajeezacademy.com   →   5.9.82.49        (Hetzner)
```

فما فيها من `supervisorctl restart all` و`varnishadm` وأسرار SSH لا موضعَ له
عندنا. اطرحها كاملة.

**والصحيح — وهو ما تعرفه أنت:** خادمٌ واحد، وثلاثُ حاويات Docker: Postgres 16
· خادم وجيز (Fastify) · Caddy (الشهادة والواجهة الساكنة). وناشرُ الإنتاج
موجودٌ في المستودَع أصلا: `deploy/deploy.sh`.

---

**ثانيا — ما أطلبه: أمرٌ واحدٌ يُنفَّذ مرّةً. لا أكثر.**

وشرطُك محفوظ: **لا يخرج من الخادم مفتاحٌ ولا سرّ.** لن أضيف شيئا إلى
GitHub، ولا تُفتَح منافذ، ولا يُعطى أحدٌ وصولا. الاتّجاهُ مقلوب: **الخادمُ
يسأل ولا يُسأل** — يفحص `origin/main` كلَّ خمس دقائق، فإن تحرّكت شغّل
`deploy/deploy.sh` بنفسه. الثمنُ الوحيد: تأخيرٌ يبلغ خمسَ دقائق بين الدمج
والنشر.

**ثالثا — التركيب: أمرٌ واحد.**

```bash
cd /opt/wajeez        # أو مسارُ المستودَع عندك
bash scripts/install-auto-deploy.sh
```

يفعل أربعةً بالترتيب، ويقف عند أوّل نقصٍ بجملةٍ تقول ما ينقص:

1. **يفحص الشروط** — الفرعُ `main`، و`deploy/.env.production` موجودٌ وفيه
   `SITE_DOMAIN`، وأنّ `git fetch` و`docker compose` يعملان **في بيئةٍ فقيرةٍ
   كبيئة cron** (`env -i … PATH=/usr/bin:/bin`). وهذا آخرُ ما يُنتبه له
   عادةً وأوّلُ ما يُسقط الجدولة: لا وكيلَ SSH ولا PATH كامل، فأمرٌ يعمل في
   طرفيّتك يفشل في cron صامتا كلَّ خمس دقائق.
2. **ينشر مرّةً واحدةً بعينك** — تُبنى الصورةُ قبل لمس ما يعمل، فإن أخفق شيءٌ
   بقي الموقعُ القديمُ يخدم.
3. **يركّب سطرَ الجدولة** — وآمنُ الإعادة: تشغيلُه مرّتين لا يضع سطرَين.
4. **يطبع كيف تقرأ وكيف تتراجع.**

إن أوقفك عند فحص `git fetch`: المفتاحُ يحتاج وكيلا — استعمل مفتاحَ نشرٍ بلا
عبارةِ مرور، أو حوّل الأصلَ إلى HTTPS برمزٍ مخزَّن. وإن أوقفك عند
`docker compose`: أضِف في أوّل `crontab` سطرَ `PATH=` يشمل موضعَه، وتحقّق أنّ
المستخدمَ في مجموعة `docker`.

**رابعا — وما يُقلع معه هذه المرّة:** حاويةُ **العامل الخلفيّ** (`worker`).
جديدةٌ في `compose.prod.yml`، الصورةُ نفسُها بأمرٍ آخر — هي التي تُرسل تذكيراتِ
الجلسات وتُفرّغ طابورَ الإشعارات وتنفّذ النشرَ المجدول. ولا `ports` لها ولا
تواجه الإنترنت، وفحصُ صحّتها مُطفأ بقصد (لا خادمَ ويبٍ فيها يُسأل).

**خامسا — كيف يُقرأ:**

السجلُّ في `~/wajeez-deploy.log`. ولا يُكتب فيه شيءٌ حين لا جديد — بقصد:
سطرٌ كلَّ خمس دقائق يُغرقه فلا يُقرأ حين يهمّ. والفشلُ يُعلَّم بعلامةٍ تُبحَث:

```bash
grep '✖' ~/wajeez-deploy.log      # نشرةٌ فشلت
grep '⚠' ~/wajeez-deploy.log      # فرعٌ غيرُ main، أو origin لا يُوصَل إليه
```

وسجلُّ العامل الخلفيّ منفصل:

```bash
docker compose -f deploy/compose.prod.yml --env-file deploy/.env.production logs -f worker
```

**سادسا — ما يحميه من نفسه:**

| الحارس | ما يمنعه |
|---|---|
| قفلُ `mkdir` ذرّيّ، يُحرَّر في `trap` | نشرتان متداخلتان — دورةُ الجدولة أقصرُ من النشرة أحيانا |
| حارسُ الفرع | خادمٌ تُرك على فرعٍ بعد فحصٍ يدويّ لا يُسحَب إليه `main` صامتا |
| احتمالُ عطبِ الشبكة | فشلُ `fetch` عابرٌ يخرج بلا إنذارٍ ويُعاد في الدورة التالية |

وما تحته — `deploy/deploy.sh` — لم يتغيّر منه حرف: نسخةٌ احتياطيّةٌ قبل
الهجرة (وإخفاقُها يوقف النشر)، ثمّ بناءُ الصورة **قبل** لمس ما يعمل، ثمّ
الهجرة، ثمّ تبديلُ الحاويات، ثمّ فحصٌ صحّيٌّ داخليٌّ فعامّ.

**سابعا — التراجع:** احذف السطرَ من `crontab`. لا شيءَ غيرُه يتغيّر، ويعود
النشرُ يدويّا كما هو اليوم.

**وأخيرا — ما لا يفعله، صراحةً:** لا رصدَ ولا تنبيهَ بعد. لو فشلت نشرةٌ في
الثالثة فجرا فالسطرُ في السجلّ هو كلُّ ما يقولها، ولن يوقظ أحدا. ذاك بندٌ
تالٍ، لا أدّعي أنّه قائم.
