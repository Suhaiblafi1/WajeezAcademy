# دليل التشغيل والتدقيق الشامل — أكاديمي وجيز

آخر تحقق كامل: 2026-08-17 — كل الأرقام أدناه نتائج أوامر أُجريت فعلا على هذا المستودع.

> ⚠️ **وما يخصّ الاستضافةَ والنشرَ في هذا الدليل سبق الانتقالَ إلى Cloudways.**
> المرجعُ للواقع الحاليّ: [`DEPLOYMENT.md`](./DEPLOYMENT.md). وبقيّةُ الدليل —
> الأوامرُ والحواجزُ والتدقيقاتُ — تعمل كما هي.

---

## 1) المعمارية

| الطبقة | التقنية | الموضع |
|---|---|---|
| الواجهة | React + Vite + Tailwind (RTL كامل) | `src/` |
| الخادم | Fastify + zod + OpenAPI على `/docs` | `server/` |
| قاعدة البيانات | PostgreSQL حقيقي عبر Prisma 7 (محول pg) | `prisma/` |
| التخزين الخاص | ملفات موقعة الروابط في `storage/private/` (خارج Git دائما) | `server/services/storage.service.ts` |

قاعدة التطوير مدمجة (`embedded-postgres`) على المنفذ 5433 وبياناتها في `.pgdata/` — لا تحتاج Docker. في الإنتاج عيّن `DATABASE_URL` ولا يُستخدم المدمج إطلاقا.

## 2) تشغيل الموقع (الواجهة)

```bash
npm install
npm run dev        # واجهة التطوير على المنفذ 3000 مع بروكسي /api → 7101
```

للمعاينة الإنتاجية: `npm run build && npm run preview` (المنفذ 4173).

## 3) تشغيل واجهة البرمجة (API)

```bash
npm run api:dev    # خادم Fastify على 127.0.0.1:7101 — يشغّل القاعدة المدمجة ويبذر الصلاحيات تلقائيا
```

فحص الحياة: `curl http://localhost:7101/api/health` — التوثيق التفاعلي: `http://localhost:7101/docs`.

## 4) قاعدة البيانات

- كل أوامر القاعدة تمر عبر الغلاف `scripts/with-db.ts` الذي يشغّل PostgreSQL المدمج ويمرر `DATABASE_URL` تلقائيا.
- لا تشغّل أوامر prisma مباشرة بلا الغلاف في التطوير.

## 5) الترحيلات (migrations)

```bash
npm run db:migrate   # تطوير: إنشاء/تطبيق ترحيلات
npm run db:deploy    # إنتاج/اختبار: تطبيق فقط
npm run db:generate  # توليد عميل Prisma
```

**والعددُ لا يُكتب هنا** — كان مكتوبا «١١ ترحيلا» والواقعُ ثمانيةٌ وخمسون، أي
رقمٌ تأخّر عن الحقيقة بسبعةٍ وأربعين ترحيلا وبقي يُقرأ. والدليلُ الذي لا يشيخ
أمرٌ يُشغَّل لا رقمٌ يُنسَخ:

```bash
ls prisma/migrations | grep -c '^2'   # كم ترحيلا
npm run ci:migrations                 # ولكلّ نموذجٍ ترحيلٌ ينشئ جدولَه
npx tsx scripts/status-checks.ts --check   # وقيدُ كلّ حالةٍ يطابق تعليقَه
```

وبوّابةُ `ci:migrations` تعمل على كلّ دفعٍ في CI: تقرأ نماذجَ المخطّط كلَّها
وتتحقّق أنّ لكلٍّ منها ترحيلا ينشئ جدولَه — فترحيلٌ ناقصٌ يسقط قبل الدمج لا
عند النشر.

**والترحيلاتُ تُطبَّق من الصفر على قاعدةٍ جديدةٍ في كلّ تشغيلِ اختبار**: ملفُّ
`server/tests/helpers/db.ts` يُسقط قاعدةَ الاختبار ويُنشئها ويَنشُر الترحيلاتِ
كلَّها قبل أوّل اختبار — فالتحقّقُ من صلاحيّتها ليس حدثا مضى، بل يقع في كلّ
مرّة.

## 6) الاستيراد (الكتالوج)

```bash
npm run catalog:import
```

مستورد حتمي وidempotent: شغّله مرتين ولا يتكرر أي سجل (مُثبت بعدّ الصفوف بعد كل تشغيل — تطابق تام وبصمة لقطة واحدة).

وأعداد ما استُورد يطبعها الأمر نفسه في آخر سطر — فاقرأها منه. وكانت مكتوبة هنا
«100 دورة · 400 وحدة · 199 سؤالا» فتقادمت بصمت بعد دمج الدورات وتوسعة البنك،
فصار الدليل يكذب على قارئه. والأعداد المعلنة في ملفات المصدر يقابلها بالفعلي
`npm run audit:diagnostic`، وهو الموضع الذي يحمرّ إن افترقا.

### في الإنتاج: يجري تلقائيا

`scripts/vercel-build.sh` يستدعي الاستيراد في آخر البناء **حين تكون البيئة `production` فقط** — لأن نُسخ المعاينة تشترك مع الإنتاج في نفس قاعدة Neon، فلو استوردت لكتبت محتوى فرع قيد المراجعة في جداول الموقع الحي. فلا حاجة إلى تشغيله يدويا بعد كل نشر.

- يمرَّر له `CATALOG_IMPORT_SKIP_MIGRATE=1`، لأن البناء نشر الهجرات قبله في حلقة إعادة محاولة؛ وإعادتها هنا تعيد سباق القفل الاستشاري الذي كُتبت تلك الحلقة لتفاديه.
- **إخفاقه لا يُسقط البناء**: الاستيراد يمسّ الجداول، والمحرك يقرأ اللقطة المنشورة — فإخفاقه لا يغيّر حرفا لدى المستخدم، بينما إسقاط البناء يمنع نشر الموقع كله. يُطبع تحذير صريح في سجل البناء ويكمل.

### والاستيراد لا ينشر

الجداول ليست ما يقرأه المحرك. بعد الاستيراد افتح `/admin/publishing` وانشر لقطة جديدة: إصدار مسودة ← تحقق بنيوي ← تحليل أثر (12 شخصية) ← نشر ذرّي. وإلا ظل المستخدم يرى الكتالوج السابق. المستورد نفسه يقول ذلك في آخر تقريره حين تفترق بصمة المستودع عن بصمة اللقطة المنشورة.

## 7) التخزين

- وثائق المتقدمين وملفات الطلاب في `storage/private/` — خارج Git عبر `.gitignore`.
- الروابط الموقعة: `storage.service.ts` يوقّع روابط مؤقتة؛ في الإنتاج عيّن `STORAGE_SECRET` وإلا وُلّد سر محلي في `storage/private/.secret`.
- يمنع منعا باتا وضع أي ملف خاص داخل `public/` — مفحوص: لا يوجد إلا favicon والشعارات وrobots وsitemap.

## 8) الحسابات التجريبية

لا توجد حسابات مبذورة في التطوير عمدا (نزاهة البيانات). التسجيل يمنح `learner` وحده، وتعيين `super_admin` من الشاشة لا يملكه إلا `super_admin` — فقاعدة بلا مدير نظام تحتاج سطر الأوامر مرة واحدة:

```bash
# سجّل الحساب من الموقع أولا، ثم:
npm run promote:super-admin -- you@example.com            # يعرض ولا يكتب
npm run promote:super-admin -- you@example.com --apply    # يضيف الدور ويسجّله في الأثر
# على الإنتاج: DATABASE_URL=postgres://… npx tsx scripts/promote-super-admin.ts you@example.com --apply
```

بعدها يُنشأ بقية الموظفين من `/admin/users` («أنشئ حسابا») بأدوارهم.

الأدوار التسعة المعرفة: `super_admin · academic_manager · diagnostic_manager · operations_manager · advisor · trainer · finance · support · learner` — مصفوفة الصلاحيات في `server/auth/permissions.ts`، ومطابقتها للبذر مثبتة باختبار `server/tests/rbac/roles-matrix.test.ts`.

## 10) النشر

المتغيرات المطلوبة في الإنتاج:

| المتغير | الغرض |
|---|---|
| `DATABASE_URL` | قاعدة PostgreSQL المُدارة (إلزامي — يلغي المدمج) |
| `WEB_ORIGIN` | أصل الواجهة لـ CORS (افتراضيا localhost:7100) |
| `NODE_ENV=production` | يفعّل كوكي secure ويخفي رموز الاستعادة من الردود |
| `STORAGE_SECRET` | سر توقيع الروابط الموقعة |
| `API_PORT` | منفذ الخادم (افتراضيا 7101) |
| `RATE_LIMIT_MAX` | السقف العام للطلبات في الدقيقة لكل عنوان (افتراضيا 300) |
| `LOGIN_RATE_MAX` | سقف نداءات `/api/auth/login` لكل ٥ دقائق لكل عنوان (افتراضيا 200 — حاجز غمر لا حاجز تخمين) |
| `REGISTER_RATE_MAX` | سقف نداءات `/api/auth/register` لكل ٥ دقائق لكل عنوان (افتراضيا 120 — حاجز غمر) |

الحماية المفعّلة: تحديد معدل عام 300 طلب/دقيقة لكل IP، و200/5د لنداءات الدخول و10/5د للتسجيل، و5/15د لاستعادة كلمة المرور، ورسائل خطأ لا تكشف وجود الحساب.

**وقفلُ الدخول ثلاثةُ سقوفٍ لا سقفٌ واحد** (المهمّة ١٧، قرارُ صاحب المنصّة في ٤ سبتمبر ٢٠٢٦) — كلُّها على نافذة ١٥ دقيقة، وأيُّها بلغ حدَّه أقفل:

| المفتاح | الحدّ | ما يمنعه |
|---|---|---|
| بريدٌ + عنوان | ٥ إخفاقات | تخمينُ كلمةِ شخصٍ بعينه من مكانه — وهو القفلُ المقصود |
| العنوان وحدَه | ٤٠ إخفاقا | رشُّ كلماتِ المرور من جهازٍ واحدٍ على بريداتٍ كثيرة |
| البريد وحدَه | ٢٥ إخفاقا | تخمينُ بريدٍ واحدٍ (مدير النظام مثلا) من شبكاتٍ كثيرة |

وكان المفتاحُ سقفا واحدا بـ«البريد **أو** العنوان» بحدّ ٥، فخمسةُ أخطاءٍ من خمسةِ أشخاصٍ على شبكةٍ واحدة تُقفل الشبكةَ كلَّها ربعَ ساعة. والسقوفُ الثلاثةُ مثبَتةٌ باختبار `server/tests/rbac/auth-throttle.test.ts` (٧ اختبارات، منها «البريءُ لا يُقفَل»).

**وسقفُ التسجيل الذاتيّ سقفان مختلفا الطبيعة** (قرارُ صاحب المنصّة في ٤ سبتمبر ٢٠٢٦)، مفتاحُهما الشبكةُ وحدَها — لأنّ البريدَ هنا يختاره المتقدّم فلا معنى لمفتاحٍ يحمله:

| ما يُعَدّ | الحدّ | ما يمنعه |
|---|---|---|
| حسابات أُنشئت فعلا | ٤٠ في الساعة · ١٠٠ في اليوم | مصنعَ الحسابات الوهميّة — وضررُ هذا الباب حجمٌ لا سرعة |
| محاولات ارتدّت بـ«البريد مسجَّل» (409) | ١٠ في ربع ساعة | **إحصاءَ البريد**: المسار يقول صراحةً إن كان البريدُ مسجَّلا |

والسجلُّ جدولٌ مستقلّ (`RegistrationAttempt`) **لا يُخزَّن فيه البريدُ المُجرَّب**، ويُقلَّم بعد ٩٠ يوما مع وظائف الاحتفاظ. **ولا يخضع للسقف ما تُنشئه الإدارةُ بصلاحيّة** (`admin.users.create` ودفعةُ CSV): السقفُ في `registerSelf` لا في `register`، وإلّا انقفلت دفعةُ مئةِ حسابٍ يُدخلها موظّفٌ من مكتبٍ واحد. مثبَتٌ بـ`server/tests/rbac/register-ceilings.test.ts` (١٠ اختبارات).

**وحقلُ الفخّ في النماذج العامّة الثلاثة** (التسجيل · استعادة كلمة المرور · طلب انضمام المدرّب): حقلٌ اسمُه `website` لا يراه إنسان — خارجَ الشاشة بموضعه (`.hp-trap`, `position:fixed`) وخارجَ شجرة الإتاحة وترتيب التنقّل — فإن جاء مملوءا رُدَّ الطلبُ بـ400 ورمز `form_rejected`، **برسالةٍ تقول للإنسان ما يفعل** إن كان مكمّلٌ في متصفّحه قد عبّأه (ولا يُتجاهَل الطلبُ صامتا: إسقاطُ طلبِ مدرّبٍ حقيقيٍّ بلا خبرٍ أسوأُ من أن يتعلّم آليّ).

> **وحدُّه صريح:** الفخُّ يُمسك ما يقود متصفّحا حقيقيّا، **ولا يُمسك من يُرسل JSON إلى المسار مباشرةً** — وهو الصنفُ الأغلب. فالحارسُ الحقيقيُّ للمسارات العامّة سقوفُها؛ ولذلك أُضيف سقفٌ خاصٌّ لـ`/api/path-drafts` (٣٠ لكلّ ربع ساعة) وكان يعتمد على السقف العامّ وحدَه. مثبَتٌ بـ`server/tests/rbac/honeypot.test.ts` (٧ اختبارات، آخرُها يُثبّت هذا الحدَّ نفسَه) و`src/tests/honeypot-field.test.ts` (٦).

> **وشرطُ صحّة كلّ ما سبق `trustProxy: 1` في `server/http/app.ts`:** بلا هذا الإعداد كان `request.ip` عنوانَ المقبس لا عنوانَ الزائر — أي عنوانَ الوسيط في كلّ بيئةٍ مُنتَجة، فتنهار مفاتيحُ «لكلّ عنوان» كلُّها إلى دلوٍ واحد. **ويقتضي هذا الإعداد أن لا يُنشَر منفذُ الخادم مكشوفا:** يُربَط على `127.0.0.1` ويُقدَّم من Caddy، وإلّا صار العنوانُ قابلا للانتحال بترويسةٍ يكتبها الزائر.

تفاصيل النطاق وSEO في `docs/DEPLOYMENT.md`.

## 11) النسخ الاحتياطي والاستعادة

**الخطة للإنتاج:** لقطة `pg_dump` يومية من القاعدة المُدارة + نسخ `storage/private/` — احتفاظ 30 يوما، واختبار استعادة شهري على قاعدة منفصلة.

**الإثبات المحلي المنفذ فعلا (2026-08-17):** سكربت `scripts/tmp/backup-restore.ts` صدّر 121 جدولا (5114 صفا) من قاعدة التطوير إلى JSON، وأنشأ قاعدة `wajeez_restore` منفصلة، وطبّق الترحيلات، وأعاد الحقن مع تعليق قيود المفاتيح مؤقتا داخل الجلسة — النتيجة: مطابقة تامة جدولا بجدول (`BACKUP_RESTORE_OK`).

## 12) تفعيل Zoom

الآن: `ManualZoomProvider` — الإدارة تدخل رابط الاجتماع ومعرفه ورمز مروره يدويا، ولا يظهر رمز المرور للمتعلم إلا قبل الموعد بنافذة محددة. للتكامل الآلي لاحقا: `ZOOM_ACCOUNT_ID` + `ZOOM_CLIENT_ID` + `ZOOM_CLIENT_SECRET` + `ZOOM_WEBHOOK_SECRET` ثم تبديل المزود في `server/services/zoom/provider.ts`.

## 13) تفعيل الدفع

مزوّدا **Moyasar** و**Stripe** منفَّذان (صفحة دفع مستضافة عندهما، والتسوية من webhook موقَّع)، ومعهما المزوّد الاختباري والتسجيل اليدوي بصلاحية `finance.payment.record`. لم يبق إلا المفاتيح: تُوضع من `/admin/integrations` أو من متغيّرات البيئة `PAYMENT_*`. **الدليل خطوة بخطوة في [`CONNECT_AR.md`](./CONNECT_AR.md).** القاعدة الثابتة: لا بطاقات تُخزن أبدا، ورجوع المتصفح ليس دليل دفع، والنجاح فقط عبر webhook موقَّع.

## 14) تفعيل البريد والرسائل

قناة **البريد منفَّذة بالكامل** (nodemailer فوق SMTP): توثيق البريد واستعادة كلمة المرور ورسائل المدربين كلها تمرّ بها، ولم يبق إلا مفاتيح SMTP — انظر [`CONNECT_AR.md`](./CONNECT_AR.md). أمّا **واتساب والرسائل القصيرة** فما زالتا `UnwiredExternalProvider` تنتظران مزوّدا. وإشعارات داخل المنصّة فعّالة أصلا.

### تفضيلات الإشعارات — وما لا يُكتَم

`GET/PUT /api/me/notification-preferences` يعرض ستّة أصناف ويحفظ تفضيل صاحب الحساب في قناة `in_app`. والجدول مصدره الوحيد `src/application/notifications/categories.ts`: كل مفتاح قالب جديد **يجب** أن يُضاف إلى صنفه هناك (اختبار خادم يفشل إن أرسل الخادم مفتاحا بلا صنف).

| الصنف | يُكتَم | القوالب |
|---|---|---|
| `sessions` · `progress` · `announcements` | نعم | التذكير والتقدّم والإعلانات |
| `money` · `certificates` · `work` | **لا** | إيصال الدفع ومستحقّات المدرّب · إصدار الشهادة · تكليف الموظّف والطلبات الواردة |

والمنع في `notification.service.ts` لا في الشاشة: صفّ تفضيل يُحفَر في القاعدة لكتم `payment.succeeded` **لا يُسكِته**، ومفتاح لا صنفَ له يمضي (السهو في التصنيف لا يُسكِت خبرا). وغياب الصفّ يعني «مُفعَّل».

لو قال أحدهم «لم يصلني إشعار»: اقرأ أثر حسابه — `notification.pref.mute` و`notification.pref.enable` مسجَّلان بالصنف والقناة والتاريخ.

## قائمة الخدمات التي تحتاج مفاتيح قبل الإطلاق العام

1. مفاتيح مزوّد الدفع + سرّ webhook (الشيفرة جاهزة — `CONNECT_AR.md`).
2. مفاتيح Zoom الأربعة (أو الاستمرار اليدوي).
3. مفاتيح SMTP (الشيفرة جاهزة) + مزوّد WhatsApp (يحتاج تنفيذا).
4. `STORAGE_SECRET` و`DATABASE_URL` إنتاجيان.
5. مراجعة قانونية لشروط الاستخدام وسياسة الخصوصية (صفحاتهما موجودة).

## 15) تدقيق «خادم بلا شاشة» — مُغلق (2026-08-20)

رُوجعت نقاط API الـ178 كلها مقابل شاشات الواجهة. النتيجة: كل نقطة إما لها شاشة أو مقصودة التصميم (نقاط عامة تفصيلية تستهلكها شاشات قائمة). آخر فجوتين أُغلقتا بقسم «الأمان والجلسات» في `src/pages/student/Account.tsx`:

- `POST /api/auth/logout-all` ← زر «الخروج من كل الأجهزة».
- `POST /api/auth/deactivate` ← «تعطيل الحساب» بتأكيد بخطوتين.

الاستثناء الموثق الوحيد المتبقي: `GET /api/trainer/me` — نقطة تفصيلية بلا شاشة مخصصة؛ بياناتها تُعرض ضمن بوابة المدرب الحالية. أولوية منخفضة، تُراجع عند أي توسعة لبوابة المدرب.

## 17) حالة الاستلام الحالية (لأي وكيل يستلم المشروع)

- آخر وسم: `v9-learner-experience` — ملاحظات الإصدار الكاملة داخل رسالة الوسم (`git tag -n99 -l v9*`).
- قاعدة الإصدارات في README: كل محطة كبرى = وسم موقّع `v<N>-<name>`؛ الوسم التالي `v10-*`.
- شجرة العمل نظيفة، كل الالتزامات مدفوعة لـ `origin/main`.
- لا حسابات مبذورة (القسم 8) — أنشئ حسابات الاختبار محليا عند الحاجة.
- المزودون المقبولون مؤقتا موثقون أعلاه (الأقسام 12–14): Zoom يدوي، دفع اختباري، قنوات خارجية غير مربوطة — ليست أخطاء بل قرارات مرحلية.
