# تقرير التدقيق الشامل — منصات أكاديمية وجيز الأربع
**التاريخ:** 2026-08-20 · **النطاق:** بوابات الإدارة والطالب والمدرب والمستشار · **الأسلوب:** فحص آلي حي (32 صفحة) + مراجعة بصرية + فحص جوال

---

## أولاً — منهجية الفحص

| المحور | الأداة | التغطية |
|---|---|---|
| أخطاء JavaScript والكونسول | Playwright مع التقاط `console.error` و`pageerror` | 32 صفحة × 4 حسابات حقيقية |
| طلبات API الفاشلة (4xx/5xx) | اعتراض الشبكة | كل صفحة |
| آثار تقنية ظاهرة للبشر | مسح نصي بأنماط: UUID، تاريخ ISO خام، `undefined/NaN`، حالات إنجليزية غير مترجمة | كل صفحة |
| فيض أفقي (كسر تخطيط) | قياس `scrollWidth` مقابل العرض | سطح مكتب 1440px + جوال 390px |
| الاتساق البصري وسلاسة الاستخدام | معاينة بصرية للقطات كل الشاشات المحورية | 14 شاشة محورية + 3 جوال |

**النتيجة الكلية:** 32 صفحة — 28 نظيفة تماماً، 4 عليها ملاحظات (3 أخطاء حقيقية أُصلحت فوراً، و1 مقبول تصميمياً).

## ثانياً — أخطاء وُجدت وأُصلحت في هذه الجولة

### 1. كشوف مستحقات المدرب — معرّف تقني خام ⛔→✅
- **الصفحة:** `/trainer/earnings`
- **المشكلة:** كل بند مالي ينتهي بمرجع داخلي ظاهر: `cohort:21131f95-18ab-48c6-8ff5-e4a754d08402` — نص آلي لا يعني شيئاً للمدرب، في صفحة **مالية حساسة** يفترض أن تكون أوضح صفحات المنصة.
- **السبب الجذري:** `Earnings.tsx` كان يعرض حقل `sourceRef` (مرجع قاعدة البيانات) بجانب وصف البند.
- **الإصلاح:** حُذف عرض المرجع من الواجهة؛ يبقى مخزناً في قاعدة البيانات للتدقيق الداخلي.
- **التحقق الحي:** ✅ «cohort:» اختفى، الوصف العربي «تدريب… — 5 متعلماً × 40 JOD» بقي.

### 2. الشعب المفتوحة للطالب — «remote» إنجليزية خام ⛔→✅
- **الصفحة:** `/student/cohorts` (صفحة يقصدها طالب محتمل ليشتري!)
- **المشكلة:** سطر «النمط: remote» — كلمة إنجليزية في بطاقة بيع موجهة للطالب.
- **السبب الجذري:** قاموس الترجمة `DELIVERY_LABELS` يعرف `online` بينما الخادم يرسل `remote` — عدم تطابق مفاتيح.
- **الإصلاح:** أُضيفت المفاتيح الفعلية للخادم (`remote → عن بعد`, `onsite → حضوري`) مع إبقاء القديمة.
- **التحقق الحي:** ✅ «النمط: عن بعد».

### 3. لوحة الكتالوج — شارة حالة خام `pending_academic_review` ⛔→✅
- **الصفحة:** `/admin/catalog` (بطاقة إحصاء المهارات)
- **المشكلة:** «76 pending_academic_review» — حالة إنجليزية بشرطة سفلية في بطاقة إحصاء تنفيذية.
- **السبب الجذري:** قاموس `STATUS_AR` ينقصه مفتاح `pending_academic_review` فسقط إلى العرض الخام.
- **الإصلاح:** أُضيفت الترجمة «بانتظار مراجعة أكاديمية».
- **التحقق الحي:** ✅ الشارة عربية.

## ثالثاً — نواقص وتحسينات مقترحة (مرتبة بالأولوية)

### أ. تستحق التنفيذ قريباً

1. **صفحات «مساري» و«مشروع التخرج» و«سيرتي» للطالب الحقيقي تعرض محاكاة.**
   الوضع الحالي مقصود (قرار المالك: تبقى وهمية)، لكن الطالب الحقيقي الذي يفتح «مساري» يرى مساراً تجريبياً لا علاقة له بشعبته الفعلية، دون أي إشارة توضح ذلك.
   **الاقتراح الدقيق:** عند وجود جلسة حقيقية، أضف لافتة رفيعة أعلى هذه الصفحات: «نموذج استرشادي لتجربة المسارات — تعلّمك الفعلي في صفحة تعلّمي». سطر واحد يزيل الالتباس كاملاً. (سهلة — 20 دقيقة)

2. **لوحتا المدرب والمستشار: فراغ كبير عند قلة البيانات.**
   عندما تكون الأرقام صفراً والقوائم فارغة، نصف الشاشة السفلي فراغ مظلم. المنصات العالمية تملأ هذا الفراغ بإرشاد.
   **الاقتراح:** بطاقة «خطواتك الأولى» تظهر فقط عندما تكون كل الأرقام صفراً (للمدرب: أكمل ملفك ← راجع شعبتك ← سجّل أول حضور). (متوسطة — ساعة)

3. **التحديث التلقائي لا يغطي قوائم الإدارة التشغيلية.**
   لوحة الأرقام الرئيسية تنبض كل 45 ثانية، لكن صفحات القوائم (التذاكر، الشعب، طلبات المدربين) تحتاج زر تحديث يدوي.
   **الاقتراح:** تطبيق خطاف `useAutoRefresh` الجاهز على `/admin/support` و`/admin/finance` و`/admin/trainers` (الأكثر تغيراً زمنياً). (سهلة — 30 دقيقة)

### ب. تحسينات تجميلية (اختيارية)

4. **سطور منهجية التقارير بأسماء جداول خام** (`Invoice حيث status=paid`, `diagnosticSnapshot`, `EnrollmentRequest`).
   هذه **مقصودة تصميمياً** — الصفحة تعلن طريقة حساب كل تقرير للشفافية أمام المدقق. لكن يمكن إبقاء الدقة مع تحسين الشكل: وصف عربي كامل + الاسم التقني بخط `monospace` صغير رمادي. (سهلة)

5. **بحث Ctrl+K متاح للإدارة فقط.**
   المدرب قد يستفيد من بحث في شعبه وطلابه، والمستشار في حالاته. البنية جاهزة (المسار مفلتر بالصلاحيات). (متوسطة — تحتاج مجموعات نتائج جديدة)

6. **كشوف المدرب التجريبية الملغاة ذات القيم الصفرية تظهر في القائمة.**
   بقايا اختبارات موثقة سابقاً. عند التشغيل الفعلي يُنصح بفلتر يخفي «ملغاة + صفر» افتراضياً مع خيار إظهارها. (سهلة — لكنها بيانات ديمو، القرار للمالك)

### ج. قرارات تحتاج المالك (لا أنفذها ذاتياً)

7. **مزود دفع حقيقي** — الدفع الحالي اختباري (`pay-test`). البنية جاهزة (idempotency + فواتير + استردادات)، ينقص حساب مزود فعلي.
8. **مزود بريد/رسائل** — التقارير المجدولة والإشعارات الخارجية تنتظر قناة إرسال؛ خدمة الإشعارات تفشل بأمان حتى تُربط.

## رابعاً — ما تأكدت سلامته (لا يحتاج شيئاً)

- **صفر أخطاء كونسول** و**صفر طلبات API فاشلة** في كل الصفحات الـ32.
- **لا فيض أفقي** في أي صفحة، سطح مكتب أو جوال.
- **لغة تصميم موحدة** عبر البوابات الأربع: نفس الترويسة، نفس إيقاع البطاقات، نفس شريط «من أين أبدأ؟» التسلسلي، نفس ألوان العلامة (تركوازي/ذهبي/ورقي).
- **حالات فارغة صادقة وموجهة** في كل مكان («الطابور نظيف — أحسنت»، «حسابك جاهز — بقيت أول شعبة») — لا شاشات ميتة.
- **الجوال:** تنقل سفلي خماسي + قائمة «المزيد»، البطاقات تتكدس سليمة، لا شيء مقصوص.
- **الصلاحيات:** كل مجموعة بحث وكل صفحة إدارية مفلترة — الطالب لا يرى شيئاً إدارياً.
- **المظهر الفاتح/الداكن** يعمل في البوابات الأربع ويثبت عبر التنقل وإعادة التحميل.
- **التواريخ والأرقام** بصيغ عربية سليمة («٣ أغسطس ٢٠٢٦»)، والمبالغ بعملتها.
- **البقايا الإنجليزية المقبولة** (لا تُعد آثاراً تقنية): `Zoom`, `JOD`, `Ctrl K`, `Enter ↵`, `CSV/XLSX`, `dd/mm/yyyy` — مصطلحات معيارية يفهمها المستخدم.

## خامساً — خلاصة الحكم العام

المنصات الأربع **متماسكة وعصرية وسهلة التسلسل**، والتدقيق لم يجد سوى 3 آثار تقنية حقيقية (أُصلحت كلها وتحقق منها حياً) وملاحظات تحسين لا تكسر شيئاً. البنية التحتية (صلاحيات، إشعارات، بحث، مظهران، نبض تحديث) الآن بمستوى المنصات العالمية.

**المرفقات:** لقطات كل صفحة في `audit/pages/` — نتائج الفحص الخام في `audit/audit-results.json` — سكربتات قابلة لإعادة التشغيل: `full-audit.mjs` · `verify-fixes.mjs` · `mobile-check.mjs`.
